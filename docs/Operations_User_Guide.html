1. Gatepass Management

Overview

A Gatepass is the document authorizing goods to leave your facility. In KINTO, gatepasses are created after invoices (Invoice-First Workflow).

Gatepass Workflow

Invoice Created → Mark Ready → Create Gatepass → Dispatch → In Transit → Delivered

Accessing Gatepasses

Navigation: Dashboard → Gatepasses Tab OR Sidebar → Production Management → Gatepasses

Creating a Gatepass

Prerequisite: An invoice must exist and be marked "Ready for Dispatch" before creating a gatepass.
1 Click "New Gatepass" button
2 Select Invoice:
  • Choose from invoices marked "Ready for Dispatch"
  • Invoice details auto-populate
3 Verify Items:
  • Review products and quantities from invoice
  • Select batch numbers for each item (FIFO allocation)
4 Select Transport Details:
  • Vehicle Number
  • Driver Name
  • Transporter (if applicable)
5 Click "Create Gatepass"

Gatepass Fields

FieldDescription
Gatepass NumberAuto-generated unique identifier
Invoice ReferenceLinked invoice number
CustomerFrom invoice
Date/TimeGatepass creation timestamp
Vehicle NumberTransport vehicle registration
Driver NameDriver details
StatusCurrent dispatch status

Gatepass Items

FieldDescription
ProductFrom invoice line items
QuantityDispatched quantity
Batch NumberSelected from available stock
Finished Good IDSpecific inventory record

FIFO Batch Allocation

When creating a gatepass, stock is allocated from oldest batches first:

  • System shows available batches sorted by date
  • Oldest batches are selected by default
  • You can manually select specific batches if needed
  • Stock is deducted upon gatepass creation

Printing Gatepass

  1. Open gatepass detail
  2. Click "Print"
  3. Options:
    • Print Gatepass only
    • Print Invoice + Gatepass together

2. Dispatch Tracking

Overview

Dispatch Tracking monitors shipments from facility exit to customer delivery. It provides a 5-stage workflow with proof of delivery capture.

Accessing Dispatch Tracking

Navigation: Sidebar → Dispatch Tracking

Dispatch Stages

Stage Description Actions Available
1. Gatepass Generated Goods packed, gatepass created Mark as Dispatched
2. Dispatched Vehicle left facility Mark as In Transit
3. In Transit On the way to customer Mark as Delivered
4. Delivered Goods reached customer Upload POD
5. POD Received Proof of delivery obtained Complete

Updating Dispatch Status

  1. Go to Dispatch Tracking screen
  2. Find the shipment
  3. Click the status update button
  4. Add any notes (optional)
  5. Confirm the update

Proof of Delivery (POD)

When goods are delivered:

  1. Click "Mark Delivered"
  2. Enter delivery timestamp
  3. Add receiver name
  4. Upload POD document/photo (optional)
  5. Capture digital signature (optional)
  6. Confirm

Dispatch Filters

FilterOptions
StatusAll, Pending, Dispatched, In Transit, Delivered
Date RangeToday, This Week, This Month, Custom
CustomerSelect specific customer
VehicleFilter by vehicle

3. Purchase Orders

Overview

Purchase Orders (POs) are used to order raw materials from suppliers. They track what was ordered, received, and pending.

Accessing Purchase Orders

Navigation: Sidebar → Production Management → Purchase Orders Tab

Creating a Purchase Order

1 Click "New Purchase Order"
2 Select Supplier:
  • Choose from registered vendors (Supplier type)
  • Supplier address auto-populates
3 Set PO Date and Expected Delivery Date
4 Add Line Items:
  • Select Raw Material
  • Enter Quantity and UOM
  • Enter Rate
  • Apply GST if applicable
5 Add Terms and Notes (optional)
6 Click "Create PO"

PO Status Workflow

Draft → Submitted → Partially Received → Fully Received → Closed

Receiving Against PO

  1. Open PO detail
  2. Click "Receive Goods"
  3. Enter received quantities per item
  4. Enter batch number for received materials
  5. Confirm receipt
  6. Inventory automatically updated

4. Sales Returns

Overview

Sales Returns handles goods returned by customers after delivery. It includes a three-stage workflow with quality segregation.

Accessing Sales Returns

Navigation: Sidebar → Sales Returns

Return Workflow

Return Initiated → Quality Check → Disposition Decision → Complete

Return Dispositions

DispositionDescriptionInventory Impact
RestockGood condition, return to stockAdded back to finished goods
RepackMinor issue, needs repackingGoes to repack queue
ScrapDamaged beyond useWritten off with evidence
SplitDifferent items have different fatesMixed handling

Creating a Sales Return

1 Click "New Return"
2 Select Original Invoice:
  • Only delivered invoices can be returned
  • Shows returnable items and quantities
3 Select Items to Return:
  • Check items being returned
  • Enter return quantity (max = invoiced quantity)
  • Enter return reason
4 Submit Return
5 Quality Inspection:
  • Inspect returned goods
  • Determine disposition for each item
  • Upload evidence if scrapping
6 Generate Credit Note:
  • System calculates credit amount
  • Credit note created automatically
  • Invoice outstanding reduced

Traceability

Returned goods maintain full traceability:

  • Original batch numbers preserved
  • Source field shows: 'sales_return_restock' or 'sales_return_repack'
  • Link to original sales return item maintained

Repack Queue

Items marked for repacking go to the Repack Queue:

Navigation: Sidebar → Inventory → Repack Queue

  1. View items pending repacking
  2. Process each item:
    • Inspect and clean packaging
    • Replace labels if needed
    • Record new packaging used
  3. Mark as "Repacked"
  4. Item moves to finished goods (source: sales_return_repack)

Scrap Inventory & Evidence

Items marked as Scrap require evidence documentation:

FieldRequiredDescription
Scrap ReasonYesWhy item is being scrapped
Photo EvidenceYesPhotos showing damage/issue
QuantityYesNumber of units scrapped
Approved ByYesSupervisor approval

Scrap items are:

  • Removed from saleable inventory
  • Recorded in scrap inventory for audit
  • Written off financially
  • Credit note generated for customer

Split Disposition

When return has items with different conditions:

  1. Select return item
  2. Enter quantity for each disposition:
    • Restock: 20 units (good condition)
    • Repack: 5 units (minor damage)
    • Scrap: 2 units (unusable)
  3. Upload evidence for scrapped items
  4. Submit - each quantity handled separately

5. Common Scenarios

Scenario 1: Complete Dispatch Flow

Situation: Invoice ready, need to dispatch goods

  1. Open invoice, ensure status is "Ready for Dispatch"
  2. Go to Gatepasses tab, click "New Gatepass"
  3. Select the invoice
  4. Verify items and batch allocation
  5. Enter vehicle and driver details
  6. Create gatepass - stock is deducted
  7. Print gatepass for driver
  8. Go to Dispatch Tracking, mark as "Dispatched"
  9. When vehicle leaves, mark "In Transit"
  10. When delivered, mark "Delivered" with POD
Scenario 2: Partial Delivery

Situation: Invoice for 100 cases, only 80 available

Note: System requires full invoice quantity for gatepass. Options:

  • Wait for remaining stock
  • Edit invoice to 80 cases, create separate invoice for 20 later
  • Cancel & Reissue with correct quantity
Scenario 3: Customer Returns Damaged Goods

Situation: Customer returns 5 damaged cases

  1. Go to Sales Returns
  2. Create new return against original invoice
  3. Select 5 cases with reason "Damaged"
  4. Submit return
  5. During quality check, mark as "Scrap"
  6. Upload damage photos as evidence
  7. Credit note generated automatically
  8. Customer account credited
Scenario 4: Ordering Raw Materials

Situation: Need to order base oil from supplier

  1. Go to Purchase Orders
  2. Create new PO
  3. Select supplier
  4. Add raw material items with quantities
  5. Submit PO
  6. When goods arrive, open PO
  7. Click "Receive Goods"
  8. Enter received quantities and batch numbers
  9. Confirm - inventory updated
Scenario 5: Digital Signature on Delivery

Situation: Customer wants signed POD (Proof of Delivery)

  1. Delivery person reaches customer
  2. Opens Dispatch Tracking on mobile
  3. Finds the dispatch entry
  4. Clicks "Mark Delivered"
  5. Customer signs on screen (finger/stylus)
  6. Capture signature as image
  7. Upload along with delivery photo
  8. Submit - Dispatch marked "Delivered"
  9. Signature stored with dispatch record

Access later: View signature in Dispatch Details → POD section

Scenario 6: Failed Delivery Re-attempt

Situation: Customer not available, delivery failed

  1. Open dispatch in Dispatch Tracking
  2. Click "Update Status"
  3. Select "Delivery Attempted"
  4. Enter reason: "Customer premises closed"
  5. Add photo evidence if needed
  6. Save - status updated
  7. Schedule re-delivery:
    • Click "Schedule Re-attempt"
    • Select new date/time
    • Add notes for driver
  8. On re-attempt, proceed with normal delivery
Scenario 7: POD with Damage Notation

Situation: Customer accepts delivery but notes 2 cases damaged

  1. Complete delivery as normal
  2. In "Mark Delivered" screen:
  3. Check "Delivery with exceptions"
  4. Enter exception: "2 cases damaged on arrival"
  5. Take photo of damaged cases
  6. Get customer signature with acknowledgment
  7. Submit delivery with notes
  8. System flags for follow-up
  9. Initiate Sales Return for 2 damaged cases
  10. Credit note generated for customer
Scenario 8: Split Disposition Return

Situation: 27 cases returned - some good, some damaged, some scrap

  1. Create Sales Return for 27 cases
  2. During quality inspection:
  3. Split disposition:
    • Restock: 20 cases (good condition)
    • Repack: 5 cases (label damage only)
    • Scrap: 2 cases (leaking, unusable)
  4. For scrap:
    • Upload damage photos
    • Get supervisor approval
  5. Submit disposition
  6. 20 cases → finished goods (restock)
  7. 5 cases → repack queue
  8. 2 cases → scrap inventory
  9. Credit note for all 27 generated
Scenario 9: Purchase Order Amendment

Situation: Vendor can only supply 80 of 100 ordered drums

  1. Open existing PO
  2. Click "Amend PO"
  3. Change quantity from 100 to 80
  4. Add amendment reason: "Vendor stock shortage"
  5. Save amendment
  6. PO shows amendment history
  7. Options for remaining 20:
    • Create new PO for later delivery
    • Source from alternate vendor
    • Cancel remaining quantity
Scenario 10: GRN Discrepancy Handling

Situation: PO for 100 drums, received 98 (2 damaged in transit)

  1. Open PO → Click "Receive Goods"
  2. Enter received qty: 98 (instead of 100)
  3. Short receipt reason: "Transit damage"
  4. Upload photos of damaged drums
  5. Complete GRN for 98
  6. Inventory updated for 98 only
  7. System prompts: "Create Debit Note?"
  8. Click Yes → Debit Note created for 2 drums
  9. Send to vendor for credit/replacement
Scenario 11: Stock Transfer Between Locations

Situation: Move 50 cases from Main Warehouse to Dispatch Area

  1. Go to Inventory → Stock Transfer
  2. From Location: Main Warehouse
  3. To Location: Dispatch Area
  4. Select product and batch
  5. Enter quantity: 50
  6. Purpose: "Pre-staging for dispatch"
  7. Confirm transfer
  8. Stock deducted from Main Warehouse
  9. Stock added to Dispatch Area
  10. Transfer record maintained
Scenario 12: Inventory Adjustment (Shortage)

Situation: Physical count shows 5 cases less than system

  1. Go to Inventory → Adjustments
  2. Click "New Adjustment"
  3. Type: Negative (shortage)
  4. Product: Select product
  5. Batch: Select affected batch
  6. Quantity: -5
  7. Reason: "Physical count variance"
  8. Reference: Stock count sheet number
  9. Attach count sheet photo
  10. Submit for approval
  11. Manager approves
  12. Inventory reduced by 5
  13. Adjustment logged in audit trail
Scenario 13: E-Way Bill Generation

Situation: Dispatching goods worth ₹55,000 (requires e-way bill)

  1. Create invoice (₹55,000 > ₹50,000 threshold)
  2. System prompts: "E-Way Bill required"
  3. Enter transport details:
    • Vehicle number
    • Transporter ID (if applicable)
    • Distance in km
  4. Click "Generate E-Way Bill"
  5. E-Way Bill number generated
  6. Valid for specified duration based on distance
  7. E-Way Bill prints with gatepass
  8. Driver carries both documents
Scenario 14: Quality Hold Release

Situation: Production batch pending QC approval for dispatch

  1. Sales team creates invoice for new batch
  2. System shows: "Batch pending QC approval"
  3. Cannot create gatepass until approved
  4. QC team completes testing
  5. Go to Finished Goods → Pending QC
  6. Find the batch
  7. Enter test results
  8. Click "Approve"
  9. Batch status: "Approved for Sale"
  10. Sales team can now create gatepass
  11. Dispatch proceeds normally
