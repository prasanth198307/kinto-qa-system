The real problem — KINTO overlap scenario
Mode 2 and Mode 3 collide for KINTO
KINTO manufactures 500ml Kinto Water bottles (Mode 2 — Finished Good). If KINTO also sells those bottles at a retail counter or through distributors, the same item needs POS fields (barcode, MRP, GST%) — making it Mode 3 as well.

If Mode 2 import creates a products row without barcode/MRP, and then Mode 3 import tries to create the same item with barcode/MRP — you get a duplicate row or a silent overwrite. Neither is acceptable.
Fix — merge Mode 2 + Mode 3 with a flag, not two separate modes
A finished good can optionally be POS-enabled. The import wizard asks: "Is this product also sold at a retail counter?" If yes → show barcode/MRP/GST fields in the same upload. One row, one import, one product record.

Mode 3 (Retail Products) then becomes purely the grocery-only path — for items that are only retail products, never manufactured in-house. This is the clean separation.
Corrected mode selector — 3 modes, clean separation
Mode Table Who uses it POS-linked? BOM-linked? Key extra fields
Raw materials raw_materials KINTO manufacturing Never As input supplier, reorder qty, storage UOM
Finished goods products type=FG KINTO output items Optional flag As output bom_id, production_uom, optionally barcode + MRP if sold retail

The products table unifies Finished Goods and Retail Products via a product_type column + pos_enabled boolean. The raw_materials table stays separate — raw materials never appear on invoices or POS, so mixing them into products creates unnecessary noise.
