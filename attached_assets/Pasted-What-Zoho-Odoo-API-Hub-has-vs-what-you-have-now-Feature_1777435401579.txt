What it would look like in your system — 4 tabs:

Tab 1 — API Catalog
Every endpoint listed with:

Method badge (GET / POST)
Description of what it does
Parameters table (name, type, required, description)
Example request (copy-paste curl command)
Example response (real JSON structure)
"Try It" button — opens a panel, fill parameters, hit Send, see live response
Tab 2 — My API Keys

Create key → choose a name + select which APIs this key can call (checkboxes)
Each key card shows: name, scopes, created date, last used, total calls this month
Revoke button
Tab 3 — Usage Analytics

Graph: API calls per day for last 30 days
Table: per endpoint — total calls, success rate, last called
Per key: which key is calling what
Tab 4 — Webhooks (future)

Register a URL
Pick events: invoice.created, payment.received, stock.low
System POSTs to your URL when that event happens
What needs to be built in the DB:

api_key_scopes       — which endpoints each key can access
api_call_logs        — every API call logged (key, endpoint, timestamp, status)
webhooks             — registered webhook URLs and events (future)

The "Try It" feature is the biggest differentiator. In Zoho you can literally open the docs, fill in a customer name and date range, click Send, and see real data come back — without writing any code. That alone converts developers into paying customers.
