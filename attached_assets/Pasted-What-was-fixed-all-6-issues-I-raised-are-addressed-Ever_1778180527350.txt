4 issues still remaining
Issue 1 — Duplicate columns in jw_cad_process
The table has both software_used (row 182) and cad_software (row 195) — same field, two column names. One needs to be dropped before migration. Similarly approval_status (row 189) and customer_approval (row 197) serve overlapping purposes — clarify which one drives the workflow gate and remove the other.
Issue 2 — jw_chit_installments missing amount_gm column
Test case #54 says "Record month-1 payment in gold gm (gm-based chit)" but the jw_chit_installments table only has a single amount numeric column. For gold-weight-based chit schemes the installment needs both amount_inr and amount_gm. Without amount_gm the gm-based chit test will fail. Add:
sqlALTER TABLE jw_chit_installments ADD COLUMN amount_gm numeric;
ALTER TABLE jw_chit_installments RENAME COLUMN amount TO amount_inr;
Issue 3 — jw_jewellery_pos_bills missing loyalty columns
The POS table has no loyalty_points_earned or loyalty_points_redeemed columns. When a loyalty member buys at the jewellery POS, points should be earned and optionally redeemed on the same bill. The loyalty program and members tables exist — just the POS billing table doesn't link to them. Add:
sqlALTER TABLE jw_jewellery_pos_bills ADD COLUMN loyalty_member_id integer;
ALTER TABLE jw_jewellery_pos_bills ADD COLUMN loyalty_points_earned numeric;
ALTER TABLE jw_jewellery_pos_bills ADD COLUMN loyalty_points_redeemed numeric;
ALTER TABLE jw_jewellery_pos_bills ADD COLUMN loyalty_redemption_value numeric;
Issue 4 — TRACES section code still needs CA verification
jw_traces_config.section_code description says 206C — but TDS on gold purchases by a buyer above ₹50L is under Section 194Q, not 206C. Section 206C covers seller-side tax collection at source which is different. Before building the auto-deduction logic, confirm with your CA which section applies to your specific use case. This is a compliance risk if wrong.
