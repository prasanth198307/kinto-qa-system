Phase 6 — Security & Compliance Foundation (Week 6–8, parallel)

6.1 PostgreSQL Row-Level Security (RLS)

  • Enable RLS on all major tables (invoices, journal_entries, hr_employees, etc.)
  • Policy: USING (tenant_id = current_setting('app.tenant_id')::int)
  • Set app.tenant_id at DB connection level in server/db.ts
  • Safety net: even if app code has tenantId bug, DB rejects cross-tenant reads

6.2 Field-Level Audit Trail

  • DB trigger on all write operations → audit_log table
  • Captures: table, record_id, field_name, old_value, new_value, changed_by, changed_at, IP
  • Priority tables: journal_entries, invoices, role_permissions, hr_payroll, nidhi_loans
  • UI: Audit log viewer with filter by table/user/date/field

6.3 Row-Level Data Isolation Within Roles

  • New permission field: data_scope (all / own / branch)
  • own = records where created_by = current user
  • branch = records where branch_id in user's branches
  • Applies to: invoices, customers, sales orders, CRM leads, HR attendance

6.4 Field-Level Permissions

  • Mask sensitive fields per role (e.g., hide salary from manager role in HR screen)
  • Config: field_permissions table (role, screen, field_name, visible: 0/1)
  • Frontend: API returns null for masked fields; UI shows "—"
